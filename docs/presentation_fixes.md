## 四、必須新增：限制頁

至少寫這四點：

1. **#11 是用舊的 event 輸入格式訓練的**：它在 10/05 14:45 完成，早於 16:13 的格式修正。#11 原始的評估前後一致，但用現行程式重新評估會不同（例：T1 car AP50 88.0 → 86.4）；在 #11 上做的 B2、B4 也有這個落差。B1、B3 已在格式一致的 #12 上確認。出處：`VERSIONS.md`、`docs/answers_for_planning_agent.md`（更正一節）。
2. **unknown 類別其實看過**：COCO 初始權重、CLIP／UniOW 的文字編碼器（Objects365 預訓練）都學過這些類別。U-Recall 和 U-AP 測的不是「從沒見過的物體」。
3. **只跑一個種子、沒有信賴區間**：0.3–0.9 點的差距（例如 AF 對 add、融合對 RGB）都可能落在雜訊內。夜間結論只有 714 張、幾乎來自同一個序列。
4. **#12 的代價**：U-Recall 提高，但 car AP50 掉 1.6，WI 和 A-OSE 都變差。另外，#1–#12 都是依測試集挑最佳權重；10/13 起改用驗證集。

## 五、用語規則（全份適用）

- mAP 或召回率的差距寫「點」，不要寫「%」。例：「+3.3 點」，不是「+3.3%」。
- 不用「零遺忘」「完美」「徹底」「無可取代」「極顯著」這類詞，除非有對應的數據或檢定。
- 程式碼頁標「真實代碼庫路徑」時，內容必須能在 repo 的那個檔案、那幾行找到；省略過的要寫「節錄」。
- 引用 commit 前先確認存在：git 紀錄從 2026-10-12（`5ba9cd1`）開始，步驟 0–9 的工作都早於第一個 commit，沒有對應的 commit。
